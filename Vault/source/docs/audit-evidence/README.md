# Audit evidence

The parent report distinguishes baseline vulnerabilities from fixed-branch regressions.

- `reproduce.ps1` extracts commit `722c40ae0f9a0403ec40d703a9749275bf032cbf` into a fresh directory under `target/audit`, adds the three evidence modules, and runs the 14 baseline assertions. These tests intentionally assert vulnerable behavior. Use PowerShell with the repo's offline Rust dependencies available. All fixtures are synthetic. The script invalidates only generated artifacts for the three local Cargo packages because shared target directories can otherwise reuse artifacts from a different archived checkout. Before testing product source after this runner, likewise run `cargo clean -p axentra-vault -p vault-core -p passkey-win` with the repository's target directory.
- Fixed security regressions live alongside the application and core source. `fixed-test-results.txt`, `fixed-build-results.txt`, `fixed-clippy-results.txt`, `fixed-interop-results.txt` and `fixed-plugin-results.txt` record the final validation. Interop tests need `AXV_INTEROP_DIR` set to the synthetic fixture directory; otherwise their wrappers skip their bodies.
- `dependency_check.py` records the advisory-equivalent scan. It requires the saved `target/audit/metadata-windows.json`, RustSec archive directory, and `rustsec-head.json` from baseline gathering. The pinned snapshot and limitations are in `dependency-results.json`. The exact semver helper is preserved in `semver/`; build it with `cargo build --offline --locked --manifest-path docs/audit-evidence/semver/Cargo.toml --target-dir target` to provide `target/debug/audit-semver.exe`. This helper is not cargo-audit or a cargo-deny policy.
- No real vaults, live authenticator credentials or owner clipboard contents were used. Native Windows and power-loss scenarios remain explicitly untested in the report.
