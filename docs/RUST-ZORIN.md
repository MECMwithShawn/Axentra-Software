## Required architecture

Use Rust for application logic, desktop hosts, background services and native browser companions. Preserve existing web interfaces where practical. Horizon remains a browser extension with browser-facing HTML/CSS/JavaScript; moving its native companion to Rust does not make its browser interface pure Rust. PDF's Python engine/UI and Spaces' .NET host require deliberate migrations with feature and data-compatibility checks.

Use native Linux APIs and packages. Windows APIs belong in target-specific modules and dependencies. A Rust wrapper around the current Python or .NET application does not complete migration. Build-time Python/Node scripts and third-party native libraries can remain when needed.

## Local packages and installation

Native x86_64 `.deb` packages have been built for Command, Horizon, Spaces, Mail, Vault, Archive, USB, CrystalWire and Ghost. PDF also has a separately named `axentra-pdf-preview` package; it does not register as the finished PDF app or replace the original implementation. These are local builds; no GitHub release was published during this work. Command, CrystalWire, Ghost, Mail, Vault, Archive, Spaces, USB and Horizon are installed on this computer. PDF preview 12 is also installed, under its separately named migration-preview identity; it is not a completed app migration. Package/workflow tests use disposable data. Command also includes local AppStream catalog entries and original app icons so Zorin Software identifies all ten local packages correctly; this is not a public release feed.

Horizon uses a signed Linux external CRX registration for Brave, with a stable extension ID. The installer registers both Rust native hosts in Brave's supported system paths. The CRX signing key is excluded from packages and output archives. Restart Brave after installation, open Horizon, and click **Connect** to grant desktop-companion access. The installer does not rewrite browser profile preferences or terminate browser sessions.

Ghost's root helper accepts only compiled catalog IDs, records exact undo data privately, and preserves unrelated policy entries. Its systemd drift timer is opt-in.

The shared build-time tool `tools/package-native-linux.py` packages Spaces, Mail, Vault, Archive, CrystalWire and Ghost from separately held source trees, includes desktop entries/icons and Command manifests, and copies Archive's Linux 7-Zip binary and license. CrystalWire includes a root capture service, systemd unit and native CLI/probe. Its recorded history and socket are restricted to root and the `adm` group; desktop use requires membership in that group. Mail uses Secret Service and fails closed if its keyring is unavailable. ClamAV is recommended by Mail and required by CrystalWire; unavailable scans are reported as errors.

Verification records are in the local task's `outputs/linux-package-verification.json` (older seven-app package record; later apps have their own verification summaries), `outputs/*-linux/verification/` (native UI and workflow evidence), and `work/logs/` (build/test logs). GUI automation used isolated X11/Xvfb sessions on Zorin 18.1 with GTK 3.24.41 and WebKitGTK 2.52.6; it does not certify Wayland behavior or clean-machine installation. APT dependency simulation passed for the four newly packaged desktop apps.

## Migration order

1. Establish repeatable Rust/Linux builds and native startup for USB; reuse its validation pattern.
2. Port Command and Archive, including XDG paths and WebKitGTK hosting, so installation/discovery and basic file workflows can be tested.
3. Port Mail and Vault with tests for secure storage, permissions, safe saves and IPC. Test live account and hardware features separately.
4. Port Ghost and CrystalWire with native Linux implementations and explicit capability limits.
5. Finish cross-platform validation and remaining workflows for Spaces' Rust host and Horizon's Rust native companion.
6. Migrate PDF against its existing document fixtures and feature tests. Keep the existing implementation available until representative documents and workflows pass.

The older [Linux preview record](LINUX-VERIFICATION.json) remains historical evidence for the earlier snapshots. It does not prove that the recovered Windows sources build here, or that any app is currently installed on this machine.

## Acceptance for each app

- `cargo test --locked` and a native `cargo build --release --locked` pass; platform-specific tests run on their target OS.
- The packaged application starts on Zorin without a development environment. Its `.desktop` entry, icon, native libraries and XDG data paths work.
- Representative workflows pass using disposable data. UI startup alone is recorded as a smoke test.
- Windows build checks continue to pass. Record X11 and Wayland results separately; do not infer Wayland validation from an Xvfb run.
- Packages declare dependencies matching their build baseline and have SHA-256 checksums. Do not label a native Ubuntu 24.04 build as compatible with older glibc without testing.
- Record gaps such as physical USB writes/boot, passkeys, mail authentication and complete network capture separately. Do not run destructive hardware tests as part of ordinary CI.

The `Rust / Linux source checks` workflow currently covers **USB only**, because it is the only app source included in this distribution checkout. It does not certify the other nine apps and does not publish releases. Add each app's checks in its source repository as it is ported.
